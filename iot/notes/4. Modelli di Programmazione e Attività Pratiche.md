## 4.1 Pattern Software e Architettura a Superloop
### L'Architettura a Superloop ed il `main.cpp` di Arduino
Nei sistemi embedded privi di sistema operativo (bare-metal), il modello di esecuzione standard è il **Superloop**. In Wiring/Arduino, questo pattern viene implementato dividendo la logica in due funzioni principali:

1. `setup()`: eseguita una sola volta all'avvio per la configurazione dei pin e delle periferiche1.
2. `loop()`: eseguita ciclicamente ed all'infinito.

La struttura reale del file `main.cpp` contenuta nel core di Arduino14 è la seguente:

```
#include <Arduino.h>

int main(void) {
    init();          // Inizializza i timer HW (es. Timer0 per millis) e l'ADC
    initVariant();   
    setup();         // Esegue la funzione di inizializzazione utente

    for (;;) {
        loop();      // Esegue continuamente il ciclo di controllo utente
        if (serialEventRun) serialEventRun();
    }
    return 0;
}
```

Organizzazione del Codice su Più Sorgenti

All'aumentare della complessità del progetto, è necessario abbandonare il file unico (`.ino`) e strutturare il codice in sorgenti multipli C/C++ (`.h` ed `.cpp`):

- **File Header (****.h****)**: contiene le dichiarazioni delle funzioni, delle macro `#define`, dei tipi personalizzati e delle strutture13.
- **File di Implementazione (****.cpp****)**: contiene il codice effettivo delle funzioni dichiarate nel relativo header.
### La Disciplina "Sense-Plan-Act"

Nello sviluppo di applicativi IoT/embedded, il ciclo principale di controllo segue la disciplina **Sense-Plan-Act**:

```
+------------------+       +------------------+       +------------------+
|      SENSE       | ----> |       PLAN       | ----> |       ACT        |
| Lettura sensori  |       | Elaborazione     |       | Pilotaggio       |
| e ingressi I/O   |       | stato / calcolo  |       | attuatori ed I/O |
+------------------+       +------------------+       +------------------+
```

1. **Sense**: Acquisizione dello stato corrente del sistema e dell'ambiente fisico leggendo i pin digitali/analogici (`digitalRead`, `analogRead`) o ricevendo pacchetti dai bus di comunicazione.
2. **Plan**: Elaborazione dei dati acquisiti, aggiornamento dello stato interno (es. transizione di una macchina a stati FSM) e decisione delle azioni da intraprendere.
3. **Act**: Invio dei comandi agli attuatori (`digitalWrite`, `analogWrite` per PWM) o invio di messaggi via seriale.
### Organizzazione di Programmi a Stati (FSM) con Interruzioni
Nei sistemi reattivi completi, il superloop viene combinato con **interruzioni esterne/timer**. La ISR gestisce la ricezione rapida degli eventi (es. pressione di un tasto o tick del timer) aggiornando variabili di stato, mentre il `loop()` principale esegue la logica FSM in modo non bloccante evitando l'uso di attese bloccanti come `delay()`.
## 4.2 Laboratorio Pratico: Input/Output e Animazioni (Lab #01 e #02)

### Step 1–3: Blinking LED e Logging Seriale
#### Step #1: Blinking del LED Interno (Pin D13)

**Obiettivo**: far lampeggiare il LED integrato sulla scheda Arduino Uno con un periodo di $1000\text{ ms}$.

```
#define LED_PIN 13

void setup() {
    pinMode(LED_PIN, OUTPUT); // Configura il pin D13 come uscita digitale
}

void loop() {
    digitalWrite(LED_PIN, HIGH); // Accende il LED (5V)
    delay(1000);                 // Attesa bloccante di 1000 ms
    digitalWrite(LED_PIN, LOW);  // Spegne il LED (0V)
    delay(1000);                 // Attesa bloccante di 1000 ms
}
```

> [!WARNING] **Limiti di** **delay()** La funzione `delay(ms)` esegue un ciclo di attesa attiva (_busy waiting_) bloccando la CPU. Durante questo tempo la scheda non può reagire ad altri ingressi, riducendo la reattività del sistema.
#### Step #3: Blinking con Logging Seriale
Invia un messaggio di testo al PC ad ogni cambio di stato del LED.

```
#define LED_PIN 13

void setup() {
    pinMode(LED_PIN, OUTPUT);
    Serial.begin(9600); // Inizializza la seriale a 9600 baud
}

void loop() {
    digitalWrite(LED_PIN, HIGH);
    Serial.println("LED ON");
    delay(1000);
    
    digitalWrite(LED_PIN, LOW);
    Serial.println("LED OFF");
    delay(1000);
}
```
### Esercizio Pratico: Animazione Sequenziale su 3 LED

**Obiettivo**: collegare 3 LED esterni (es. su pin D10, D11, D12) ed animarli in sequenza avanti e indietro, mantenendo un solo LED acceso alla volta.

```
const int ledPins[] = {10, 11, 12};
const int numLeds = 3;

void setup() {
    for (int i = 0; i < numLeds; i++) {
        pinMode(ledPins[i], OUTPUT);
    }
}

void loop() {
    // Scorrimento in avanti (D10 -> D11 -> D12)
    for (int i = 0; i < numLeds; i++) {
        digitalWrite(ledPins[i], HIGH);
        delay(200);
        digitalWrite(ledPins[i], LOW);
    }
    // Scorrimento all'indietro (D11 -> D10)
    for (int i = numLeds - 2; i > 0; i--) {
        digitalWrite(ledPins[i], HIGH);
        delay(200);
        digitalWrite(ledPins[i], LOW);
    }
}
```

### Step 4: Gestione del Pulsante e LED (`digitalRead`)
Gestione di un ingresso digitale da pulsante collegato con resistenza di pull-down da $10\text{ k}\Omega$.

```
const int buttonPin = 2; // Pin collegato al pulsante
const int ledPin = 13;    // Pin collegato al LED

int buttonState = 0;

void setup() {
    pinMode(ledPin, OUTPUT);
    pinMode(buttonPin, INPUT); // Configurato come ingresso
}

    }
}
```
### Step 5: Controlled Fading (Potenziometro + PWM)

**Obiettivo**: leggere la tensione da un potenziometro (ingresso analogico `A0`)310 e variare proporzionalmente la luminosità di un LED collegato a un pin PWM (pin `9`).

> [!NOTE] **Conversione di Mappatura**

- `analogRead(A0)` acquisisce il valore tramite l'ADC a 10-bit proponendo un range da `0` a `1023`.
- `analogWrite(9, val)` richiede un valore PWM a 8-bit compreso tra `0` e `255`.
- Si utilizza la funzione `map(val, 0, 1023, 0, 255)`.
![[Pasted image 20261011154418.png]]

```
#define POT_PIN A0
#define LED_PIN 9 // Deve supportare la PWM (pin contrassegnati con ~)

int current = -1;

void setup() {
    pinMode(LED_PIN, OUTPUT);
}

void loop() {
    // Legge il potenziometro (0..5V mappati in 0..1023)
    int newValue = analogRead(POT_PIN);
    
    if (newValue != current) {
        current = newValue;
        // Mappa il range analogico sull'uscita PWM (0..255)
        int outputValue = map(current, 0, 1023, 0, 255);
        analogWrite(LED_PIN, outputValue); // Varia la luminosità
    }
}
```
## 4.3 Laboratorio Pratico: Interruzioni e Timer (Lab #02 e #03)

### Step 6: Conteggio Eventi tramite Interrupt ed Atomicità

Conteggio delle pressioni di un pulsante mediante interruzione esterna sul **Pin D2 (INT0)**.

```
#define BUTTON_PIN 2

volatile int count = 0; // Variabile modificata all'interno della ISR
int prev = 0;

void inc() {
    count++; // ISR associata all'interrupt
}

void setup() {
    Serial.begin(9600);
    // Registra la ISR sul pin D2 in corrispondenza del fronte di salita (RISING)
    attachInterrupt(digitalPinToInterrupt(BUTTON_PIN), inc, RISING);
}

void loop() {
    // SEZIONE CRITICA: Lettura atomica della variabile condivisa
    noInterrupts();
    int current = count;
    interrupts();

    if (current != prev) {
        Serial.println(current);
        prev = current;
    }
}
```
#### Il Problema del Rimbalzo Meccanico (_Bouncing_) e Software Debouncing

Quando un pulsante meccanico viene premuto, le lamelle interne subiscono una serie di micro-rimbalzi meccanici per alcuni millisecondi. Questo genera una sequenza rapida di interrupt spurii che incrementano erroneamente il contatore più volte ad ogni singola pressione.

==Soluzione via Software Debouncing (Filtro Temporale):==

Si ignorano gli impulsi che arrivano entro un intervallo di guardia fisso (es. $200\text{ ms}$) dal primo impulso valido.

```
#define BUTTON_PIN 2

volatile int count = 0;
volatile unsigned long lastInterruptTime = 0;

void incDebounced() {
    unsigned long interruptTime = millis();
    // Se l'interrupt arriva prima di 200ms dall'ultimo, è un rimbalzo
    if (interruptTime - lastInterruptTime > 200) {
        count++;
        lastInterruptTime = interruptTime;
    }
}

void setup() {
    Serial.begin(9600);
    attachInterrupt(digitalPinToInterrupt(BUTTON_PIN), incDebounced, RISING);
}

void loop() {
    // Logica di stampa nel superloop
}
```
#### Gestione Estesa degli Interrupt: Libreria `EnableInterrupt`

Mentre l'ATmega328P offre solo 2 pin dedicati ad interrupt esterni diretti (D2 ed D3)27, la libreria `EnableInterrupt`permette di configurare le interruzioni su **qualsiasi pin I/O** sfruttando la funzionalità hardware _Pin Change Interrupt_(PCINT) del microcontrollore.
### Step 7: Event-Driven Blinking con Timer Hardware (`TimerOne`)

Uso del **Timer1 (a 16-bit)** per far lampeggiare un LED tramite interrupt di timer senza occupare la CPU con cicli `delay()`.

**Libreria**: `TimerOne.h` (da installare tramite Library Manager dell'IDE).

```
#include "TimerOne.h"

#define LED_PIN 13
boolean flagState = false;

// Routine di interrupt del timer (ISR)
void blinky() {
    if (!flagState) {
        digitalWrite(LED_PIN, HIGH);
    } else {
        digitalWrite(LED_PIN, LOW);
    }
    flagState = !flagState;
}

void setup() {
    pinMode(LED_PIN, OUTPUT);
    // Inizializza il Timer1 impostando il periodo a 1.000.000 us (1 secondo)
    Timer1.initialize(1000000);
    // Associa la funzione blinky all'interrupt del timer
    Timer1.attachInterrupt(blinky);
}

void loop() {
    // Il loop principale rimane completamente libero per eseguire altri task!
}
```

## 4.4 Laboratorio Pratico: Periferiche Avanzate e Gestione Memoria (Lab #03)
### Step 8–9: Gestione del Risparmio Energetico (_Sleep Modes_)
#### Step #8: Deep Sleep (`SLEEP_MODE_PWR_DOWN`)

Mette la MCU nel livello minimo di consumo (arresta tutti i clock). Il risveglio avviene unicamente premendo il pulsante collegato al pin di interrupt D2.

```
#include <avr/sleep.h>

void wakeUp() {
    // ISR di risveglio vuota: serve solo a interrompere lo sleep
}

void setup() {
    Serial.begin(9600);
    pinMode(2, INPUT);
    attachInterrupt(digitalPinToInterrupt(2), wakeUp, RISING);
}

void loop() {
    Serial.println("POWER DOWN IN 1s ...");
    Serial.flush(); // Attende il completamento della trasmissione seriale
    delay(1000);

    set_sleep_mode(SLEEP_MODE_PWR_DOWN); // Imposta la modalità Deep Sleep
    sleep_enable();                      // Abilita lo bit di sleep
    
    sleep_mode();                        // La MCU entra in pausa qui!

    /* Il programma riprende da questo punto dopo il risveglio */
    sleep_disable();                     // Disabilita lo sleep
    Serial.println("WAKE UP");
}
```

#### Step #9: Light Sleep (`SLEEP_MODE_IDLE`)

Arresta la CPU lasciando attivi i timer hardware ed i moduli di periferica. Utile per scheduler e programmi temporizzati.

```
#include <avr/sleep.h>
#include <avr/power.h>

void sleepLight(void) {
    set_sleep_mode(SLEEP_MODE_IDLE);
    sleep_enable();

    // Disabilita i moduli HW non necessari per risparmiare energia
    power_adc_disable();
    power_spi_disable();
    power_timer0_disable();
    power_timer2_disable();
    power_twi_disable();

    sleep_mode(); // Va in idle

    /* Al risveglio riabilita tutte le periferiche */
    sleep_disable();
    power_all_enable();
}
```

### Step 11–12: Periferiche I2C e Display LCD

#### Step #11: I2C Scanner

Scansiona tutti gli indirizzi a 7-bit del bus I2C (da `1` a `127`) per rilevare gli indirizzi hardware dei dispositivi collegati (pin `A4/SDA` ed `A5/SCL`).

```
#include <Wire.h>

void setup() {
    Wire.begin(); // Inizializza il bus I2C in modalità Master
    Serial.begin(9600);
    Serial.println("\nI2C Scanner");
}

void loop() {
    byte error, address;
    int nDevices = 0;

    for (address = 1; address < 127; address++) {
        Wire.beginTransmission(address);
        error = Wire.endTransmission();

        if (error == 0) {
            Serial.print("Dispositivo I2C trovato all'indirizzo 0x");
            if (address < 16) Serial.print("0");
            Serial.println(address, HEX);
            nDevices++;
        }
    }
    if (nDevices == 0) Serial.println("Nessun dispositivo I2C trovato\n");
    delay(5000);
}
```

Ottimizzazione della Memoria SRAM e la Macro `F()`

Poiché l'ATmega328P dispone di soli $2\text{ KiB}$ **di memoria RAM (SRAM)**, l'invio di stringhe di testo costanti tramite `Serial.print("Messaggio lungo...")` alloca ogni carattere direttamente nella SRAM saturandola rapidamente.

La soluzione: Macro `F()`

Utilizzando la wrapper macro `F()` attorno alle stringhe costanti, si forza il compilatore a memorizzare e leggere le stringhe **direttamente dalla memoria Flash** (32 KiB) risparmiando preziosa memoria SRAM.

```
// ERRATO: La stringa risiede in SRAM consumando memoria RAM
Serial.println("Messaggio di log molto lungo che occupa RAM");

// CORRETTO: La stringa rimane memorizzata nella Flash
Serial.println(F("Messaggio di log memorizzato in Flash!"));
```
