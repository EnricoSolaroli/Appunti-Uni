## 3.1 Architettura Interna della MCU (Focus: ATmega328P / Arduino Uno)

==Integrazione Single-Chip==: a differenza dei microprocessori generici dei PC (che richiedono chip esterni separati per RAM, ROM e per la gestione delle periferiche), un **Microcontrollore (MCU)** integra **su un unico chip di silicio** tutte le componenti necessarie per il funzionamento autonomo di un sistema computazionale:
![[Pasted image 20261008190322.png]]
- **CPU**: Unità centrale di elaborazione a 8-bit. ![[Pasted image 20261008190430.png|338]]
- **Unità di Memoria**: Flash, SRAM ed EEPROM integrate nello stesso integrato.
- **Periferiche di Input/Output**: Porte GPIO digitali e convertitori analogico-digitali (ADC).
- **Timer Hardware**: Moduli di conteggio e generazione temporale.
- **Bus di Comunicazione Seriale**: Controller hardware per UART, SPI e I2C (TWI).
- **Circuiteria di Clock e Alimentazione**: Oscillatore e moduli di gestione dell'energia.
![[Pasted image 20261008190552.png]] _(diagramma ad albero dell'architettura interna dell'ATmega328P con CPU AVR, memorie e registri I/O)_
### Architettura Harvard vs Von Neumann e Modello di Esecuzione

I microcontrollori AVR come l'ATmega328P adottano un'**Architettura Harvard**, che costituisce una variante del modello classico di Von Neumann:

```
      ARCHITETTURA VON NEUMANN                   ARCHITETTURA HARVARD
  +-------------------------------+         +----------+     +----------+
  | Memoria Unificata             |         | Memoria  |     | Memoria  |
  | (Codice + Dati sullo stesso   |         | Istruzioni|    | Dati     |
  |  bus di sistema)              |         | (FLASH)  |     | (SRAM)   |
  +-------------------------------+         +----+-----+     +----+-----+
                 |                               |                |
                 v                               +-------+  +-----+
              +-----+                                    |  |
              | CPU |                                    v  v
              +-----+                                  +------+
                                                       | CPU  |
                                                       +------+
```

1. **Modello Von Neumann (Ciclo Fetch-Decode-Execute)**:
    - La CPU esegue le istruzioni mediante un ciclo continuo suddiviso in tre fasi: **Fetch** (prelevamento dell'istruzione dalla memoria), **Decode** (decodifica dell'operazione e dei registri coinvolti) ed **Execute**(esecuzione tramite l'ALU e aggiornamento dello stato). ![[Pasted image 20261008190830.png|404]]
2. **Architettura Harvard**:
    - **Separazione Fisica delle Memorie e dei Bus**: La memoria delle istruzioni (programma) e la memoria dei dati sono fisicamente distinte e collegate alla CPU tramite bus separati.
    - **Accesso Simultaneo**: Poiché i bus sono separati, la CPU può leggere un'istruzione di programma e accedere a una variabile in RAM contemporaneamente durante lo stesso ciclo di clock, incrementando notevolmente le prestazioni. ![[Pasted image 20261008190851.png]]
#### Set di Istruzioni (ISA) e Registri della CPU AVR8
L'architettura **AVR8** dell'ATmega328P è una CPU di tipo **RISC** (Reduced Instruction Set Computer) a 8-bit operante a $16\text{ MHz}$:

- **32 Registri General-Purpose a 8-bit (**$R0 \div R31$**)**: Tutte le operazioni aritmetico-logiche avvengono direttamente tra questi registri interni alla CPU senza dover accedere ogni volta alla memoria RAM.
- **Registri Speciali**:
    - **PC (Program Counter)**: A 16 o 22 bit, punta all'indirizzo dell'istruzione da eseguire nella Flash.
    - **SP (Stack Pointer)**: Punta al vertice dello stack in RAM per la gestione delle chiamate a funzione ed interrupt.
    - **SREG (Status Register)**: Registro di stato a 8 bit contenente i flag aritmetici (es. `C` Carry, `Z` Zero) e il flag **I** **(Global Interrupt Enable)**.
### Mappa e Gestione della Memoria nell'ATmega328P
L'ATmega328P gestisce tre tipi di memoria fisicamente e funzionalmente differenti:

| Tipo Memoria | Dimensione      | Volatilità   | Velocità / Cicli                                           | Utilizzo Principale                                                                                |
| ------------ | --------------- | ------------ | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| **Flash**    | $32\text{ KiB}$ | Non Volatile | Lettura veloce, Scrittura lenta (max $\sim 100.000$ cicli) | Conservazione del codice di programma eseguibile (di cui $0.5\text{ KB}$ riservati al bootloader). |
| **SRAM**     | $2\text{ KiB}$  | Volatile     | Molto veloce ($\sim 2$ cicli di clock)                     | Memorizzazione delle variabili globali, variabili locali, Heap e Stack di esecuzione.              |
| **EEPROM**   | $1\text{ KiB}$  | Non Volatile | Accesso lento                                              | Dati persistenti a lungo termine letti/scritti via libreria `EEPROM.h`                             |

> [!WARNING] **Vincolo sulla SRAM** Con soli $2\text{ KiB}$ **di SRAM**, l'uso della memoria temporanea deve essere estremamente disciplinato. Una ricorsione profonda o l'allocazione incontrollata di stringhe di testo rischia di saturare lo stack provocando il reset o il blocco imprevedibile della MCU.

![[Pasted image 20261008191040.png]] _(organizzazione degli indirizzi di memoria tra Flash, EEPROM e lo spazio Data Memory che mappa registri CPU, registri I/O e SRAM)_
### Piattaforma Arduino Uno, Bootloader e Framework Wiring

- **Caratteristiche Piattaforma**: Scheda di sviluppo basata su MCU ATmega328P a 8-bit con frequenza di clock di $16\text{ MHz}$, dotata di porta USB, regolatore a $5\text{ V}$ e connettore ICSP.
- **Bootloader**: Piccolo firmware (circa $512\text{ byte}$) pre-memorizzato nella porzione alta della memoria Flash. All'atto del reset della scheda, il bootloader viene eseguito per primo: se rileva comandi inviati via seriale dall'IDE del PC, scarica il nuovo programma binario nella Flash; altrimenti avvia l'esecuzione dell'ultimo programma salvato.
- **Framework Wiring e Compilazione**:
    - Wiring è un framework C/C++ open-source che mette a disposizione API ad alto livello per il controllo dell'hardware.
    - La compilazione viene eseguita dal compilatore incrociato **avr-gcc**.
    - **Il** **main()** **Nascosto**: Il compilatore inserisce automaticamente una funzione `main()` invisibile al programmatore che inizializza le periferiche hardware (`init()`), esegue una sola volta la procedura `setup()` e poi esegue `loop()` all'interno di un ciclo infinito `for(;;)`:

```
// Struttura reale del main() generata da Wiring/Arduino
int main(void) {
    init();         // Inizializza i timer HW (es. Timer0 per millis) e ADC
    initVariant();   
    setup();        // Esegue la funzione di configurazione dell'utente

    for (;;) {
        loop();     // Esegue continuamente il ciclo di controllo dell'utente
        if (serialEventRun) serialEventRun();
    }
    return 0;
}
```

## 3.2 General-Purpose I/O (GPIO) e Segnali Analogici
### Programmazione dei Pin Digitali e Registri di Porta
L'Arduino Uno dispone di **14 pin digitali** (pin $0 \div 13$) che operano a una tensione nominale di $5\text{ V}$ e possono erogare o assorbire fino a $40\text{ mA}$ per pin.

A livello hardware dell'ATmega328P, le linee di I/O sono raggruppate in **3 Porte a 8 bit**:

- **PORT D**: Gestisce i pin digitali $0 \div 7$ (etichettati come $\text{PD0} \div \text{PD7}$).
- **PORT B**: Gestisce i pin digitali $8 \div 13$ (etichettati come $\text{PB0} \div \text{PB5}$).
- **PORT C**: Gestisce i pin analogici $A0 \div A5$ (etichettati come $\text{PC0} \div \text{PC5}$).
![[Pasted image 20261009120112.png]] _(diagramma dei piedini del chip con corrispondenza tra i pin Arduino e le porte B, C, D)_

Ogni porta è controllata da **3 Registri Mappati in Memoria**: (x si intende la porta, per esempio può essere la D -> DDRD, PORTD, PIND)

1. **DDRx** **(Data Direction Register)**: Definisce la direzione dei pin. Scrivere `0` configura il pin come `INPUT`; scrivere `1` lo configura come `OUTPUT`.
2. **PORTx** **(Data Register)**:
    - Per i pin configurati come **OUTPUT**: scrivere `1` imposta la tensione del pin a `HIGH` ($5\text{ V}$); scrivere `0` imposta il pin a `LOW` ($0\text{ V}$).
    - Per i pin configurati come **INPUT**: scrivere `1` attiva la resistenza interna di **Pull-Up** del pin; scrivere `0` la disattiva.
3. **PINx** **(Input Pins Address)**: Registro di sola lettura che contiene il valore logico corrente letto dall'esterno sui pin di ingresso (`1` per HIGH, `0` per LOW).

Le funzioni Wiring `pinMode(pin, mode)`, `digitalWrite(pin, value)` e `digitalRead(pin)` convertono queste operazioni scrivendo/leggendo direttamente su questi registri.
### Gestione degli Ingressi Analogici e ADC
Un segnale analogico varia in modo continuo nell'intervallo di tensione tra $0\text{ V}$ (GND) e $5\text{ V}$($V_{CC}$). Per essere elaborato dalla CPU digitale, deve essere convertito da un **Analog-to-Digital Converter (ADC)**.

- **Specifiche ADC ATmega328P**: L'Arduino Uno dispone di **6 ingressi analogici** (pin $A0 \div A5$) multiplexati verso un singolo ADC interno a **10 bit di risoluzione**.
- **Conversione Discreta**: L'intervallo $0 \div 5\text{ V}$ viene mappato discretamente in un valore intero compreso tra $0$ e $1023$ ($2^{10}-1$):

$$\text{Valore Digitale ADC} = \text{round}\left( \frac{V_{in}}{V_{REF}} \times 1023 \right)$$

- **Pin AREF**: Il pin `AREF` consente di modificare la tensione di riferimento massima ($V_{REF}$) usata dall'ADC per adattare la scala di conversione.
- **Funzione API**: `int val = analogRead(pinA0);`. Per rimappare il range letto su un altro intervallo applicativo si utilizza la funzione utility `map(val, 0, 1023, min_out, max_out)`.
### Generazione di Segnali PWM (Pulse Width Modulation)
I pin digitali di una MCU non possono erogare una vera tensione analogica variabile in modo continuo2126. Per emulare un'uscita analogica si utilizza la tecnica della **Pulse Width Modulation (PWM)**, generando un'onda quadra ad alta frequenza con un rapporto di forma variabile (**Duty Cycle**).

![[Pasted image 20261009120728.png]]
- **Formula della Tensione Media Equivalentemente Emulata**:

$$V_{medio} = \text{Duty Cycle} \times V_{CC} = \left( \frac{\text{Tempo HIGH}}{\text{Periodo Totale}} \right) \times 5\text{ V}$$

- **Pin PWM su Arduino Uno**: I pin **3, 5, 6, 9, 10 e 11** sono abilitati alla PWM a 8-bit.
- **Funzione API**: `analogWrite(pin, valore);` dove `valore` varia da `0` (Duty Cycle 0%) a `255` (Duty Cycle 100%).
- _Applicazioni tipiche_: Controllo della luminosità dei LED, regolazione della velocità di motori in corrente continua (vedere nel file 4).
## 3.3 Meccanismo delle Interruzioni (Interrupts)
### Concetti Fondamentali e Flusso di Esecuzione
L'**Interrupt** è il meccanismo hardware fondamentale che consente al microcontrollore di reagire immediatamente ed in modo asincrono ad eventi esterni o interni, senza dover impegnare la CPU in cicli di controllo continui (polling).

```
   Flusso Ciclo Principale (Superloop)               Routine di Interrupt (ISR)
+------------------------------------+
|  Istruzione N                      |
|  Istruzione N+1                    |
|  ===> SEGNALE DI INTERRUPT (IRQ)   |
|        - Salva PC su Stack         |
|        - Salva Stato               |----------------> +----------------+
|                                    |                | Salva Contesto     |
|                                    |                | Esegue Codice ISR  |
|                                    |<---------------| Ripristina Contesto|
| Istruzione N+2 (Ripresa esecuzione)|                  +---------------+
+------------------------------------+
```

1. **IRQ (Interrupt Request)**: Segnale hardware generato da una periferica (pin I/O, timer, UART) inviato alla CPU.
2. **Sospensione e Salvataggio**: La CPU completa l'istruzione in corso, sospende il flusso del programma principale, salva l'indirizzo della successiva istruzione (Program Counter) nello Stack in RAM e disabilita temporaneamente le interruzioni28.
3. **Vettore di Interrupt e ISR (Interrupt Service Routine)**: La CPU consulta la **Tabella dei Vettori di Interrupt**(mappata nei primi indirizzi della Flash), individua l'indirizzo della funzione associata (ISR) ed esegue il relativo codice2829.
4. **Ripristino**: Terminata la ISR, la CPU ripristina lo stato originale e riprende l'esecuzione del programma dal punto in cui era stato interrotto28.
### Interrupt Esterni su Arduino / ATmega328P
L'ATmega328P supporta hardware dedicato per interruzioni esterne su **due pin specifici**:

- **INT0**: Pin Digitale **2**.
- **INT1**: Pin Digitale **3**.

> [!NOTE] Tramite librerie estese (come `EnableInterrupt`) è possibile attivare la funzionalità _Pin Change Interrupt_(PCINT) su tutti i pin I/O della scheda.

Registrazione della ISR in Wiring:

```
attachInterrupt(digitalPinToInterrupt(pin), ISR_function, mode);
```

- **Modalità di Innesco (mode)**:
    - `RISING`: Attiva l'interrupt sul fronte di salita (passaggio da `LOW` a `HIGH`).
    - `FALLING`: Attiva l'interrupt sul fronte di discesa (passaggio da `HIGH` a `LOW`).
    - `CHANGE`: Attiva l'interrupt a qualsiasi variazione di stato logico.
    - `LOW`: Attiva continuamente l'interrupt finché il pin rimane a livello basso.
### Sezioni Critiche, Race Conditions e Qualificatore `volatile`
Quando una variabile è condivisa tra il flusso di esecuzione principale (`loop()`)e una routine di interruzione (`ISR`), si verificano problemi di concorrenza:

1. **Problematiche di Corsa (Race Condition)**: Poiché la CPU a 8-bit impiega più istruzioni macchina per leggere o scrivere variabili a 16 o 32 bit (es. `int` o `long`), un interrupt può scattare proprio a metà dell'operazione di lettura/scrittura, corrompendo il valore della variabile.
2. **Sezioni Critiche e Disabilitazione Interruzioni**: Un blocco di codice che accede a variabili condivise è una **Sezione Critica** e deve essere reso atomico disabilitando temporaneamente gli interrupt:

```
noInterrupts(); // Disabilita gli interrupt (esegue istruzione assembly CLI)
int val_sicuro = variabile_condivisa; // Accesso atomico
interrupts();   // Riabilita gli interrupt (esegue istruzione assembly STI)
```

1. **Il Qualificatore** **volatile**: Ogni variabile modificata all'interno di una ISR deve essere dichiarata con la parola chiave **volatile**. Questo forza il compilatore C/C++ a leggere/scrivere la variabile sempre direttamente dalla RAM anziché ottimizzarla memorizzandola temporaneamente nei registri della CPU.

```
volatile int conteggioEventi = 0; // Dichiarazione corretta per ISR
```
### Vincoli e Regole di Progettazione per le ISR
> [!WARNING] **Regole tassative per la scrittura delle ISR**

1. **Zero Annidamento (****No Interrupt Nesting****)**: Nell'architettura AVR8, quando una ISR va in esecuzione gli interrupt generali vengono disabilitati automaticamente dalla CPU; pertanto **un interrupt non può essere interrotto da un altro interrupt**.
2. **Incompatibilità con** **delay()**: La funzione `delay()` si blocca all'interno di una ISR perché il suo funzionamento si basa sui timer che richiedono gli interrupt attivi.
3. **Uso di** **delayMicroseconds()**: Se è indispensabile introdurre una brevissima attesa all'interno di una ISR, si deve usare `delayMicroseconds()` che esegue un ciclo di conteggio istruzioni senza usare interrupt.
4. **Esecuzione Ultrarapida**: Le ISR devono essere estremamente brevi ed essenziali per mantenere bassa la latenza di risposta del sistema (_low interrupt latency)._
## 3.4 Timer e Moduli Hardware Correlati
### Architettura dei Timer Hardware nell'ATmega328P
Un **Timer** è un contatore registico hardware indipendente che viene incrementato automaticamente ad ogni impulso del segnale di clock.

L'ATmega328P integra **3 Timer Hardware**:

- **Timer0**: Contatore a **8-bit** (valori da 0 a 255)6. Utilizzato dal framework Arduino per incrementare la funzione `millis()` e per il PWM sui pin 5 e 6.
- **Timer1**: Contatore a **16-bit** (valori da 0 a 65535). Utilizzato per temporizzazioni ad alta precisione e PWM sui pin 9 e 10.
- **Timer2**: Contatore a **8-bit** (valori da 0 a 255). Utilizzato per la generazioni di frequenze audio e PWM sui pin 3 e 11.

### Prescaler e Modalità CTC (Clear Timer on Compare Match)
I contatori hardware avanzano alla frequenza del clock di sistema ($16\text{ MHz}$), il che significa che un contatore a 8-bit andrebbe in overflow (da 255 a 0) in soli $16.1\,\mu\text{s}$. Per generare intervalli temporali umani si utilizzano due meccanismi:

1. **Prescaler (Divisore di Frequenza)**: Modulo hardware che divide la frequenza del clock principale per un fattore fisso $N \in \{1, 8, 64, 256, 1024\}$:
$$f_{timer} = \frac{16.000.000\text{ Hz}}{\text{Prescaler}}$$

2. **Modalità CTC (Clear Timer on Compare Match)**: In modalità CTC, il contatore del timer viene azzerato automaticamente e genera un interrupt non appena il suo valore raggiunge la soglia impostata nel registro **OCRxA** **(Compare Match Register)**.
![[Pasted image 20261009121958.png]]
_( tabella della selezione del Prescaler tramite i bit CSx2, CSx1, CSx0 nei registri TCCRxB)_
### Formule per la Configurazione del Timer in Modalità CTC:
Data la frequenza di interrupt desiderata $f_{desiderata}$ (in Hz), il valore da caricare nel registro `OCRxA` si calcola come:
$$\text{OCRxA} = \frac{16.000.000\text{ Hz}}{\text{Prescaler} \times f_{desiderata}} - 1$$
- **Esempio Pratico (Generare un interrupt di 1 Hz - 1 secondo)**:
    - Usiamo **Timer1** (16-bit, valore max 65535).
    - Selezioniamo un **Prescaler = 1024**:
    - $\text{OCR1A} = \frac{16.000.000}{1024 \times 1} - 1 = 15625 - 1 = 15624$.
    - Poiché $15624 < 65536$, il valore rientra perfettamente nella capacità del Timer.
### Implementazione di `millis()` e Watchdog Timer
- **Funzionamento di** **millis()**: La funzione `millis()` restituisce il numero di millisecondi trascorsi dall'accensione della scheda. In Arduino è implementata leggendo una variabile contatore aggiornata dalla ISR dell'interrupt di overflow generato dal **Timer0**.
- **Watchdog Timer (WDT)**:
    - È un timer hardware completamente indipendente con un proprio oscillatore interno a consumo ridottissimo.
    - Funziona come un "timer di sicurezza": il programma deve inviare un segnale di reset al Watchdog a intervalli regolari.
    - Se il sistema si blocca in un ciclo infinito o in deadlock, il programma smette di resettare il Watchdog; allo scadere del tempo di timeout (_Watchdog Reset_), il Watchdog forza un **reset hardware completo dell'MCU**, riavviando il sistema.
## 3.5 Comunicazione Seriale e Gestione dell'Energia
### Comunicazione Seriale Asincrona (UART)
L'**UART (Universal Asynchronous Receiver-Transmitter)** è il modulo di comunicazione seriale asincrono utilizzato per scambiare dati tra la MCU e l'host PC tramite cavo USB.

- **Linee Hardware**: Utilizza i pin **0 (RX)** per la ricezione e **1 (TX)** per la trasmissione.
- **Baud Rate**: Indica la velocità di trasmissione espressa in bit al secondo (bps). I due dispositivi in comunicazione devono essere rigorosamente configurati allo stesso Baud Rate (es. `9600`, `115200` bps).
- **Uso in Wiring**: Gestito tramite l'oggetto `Serial` (`Serial.begin(9600);`, `Serial.println();`), essenziale per il logging ed il debugging su **Serial Monitor**.
### Comunicazione Seriale Sincrona: Bus I2C e SPI
I bus sincroni utilizzano una linea di clock condivisa per coordinare il trasferimento dei bit.

```
                     Bus Seriali Sincroni
                              |
     +------------------------+------------------------+
     |                                                 |
  BUS I2C (TWI)                                    BUS SPI
  - 2 Linee (SDA, SCL)                             - 4 Linee (MOSI, MISO, SCK, SS)
  - Architettura Master/Slave ad indirizzi (7-bit) - Architettura Master/Slave con linea di selezione
  - Velocità moderata (100-400 kbps)               - Velocità elevatissima (molti Mbps)
  - Pin Arduino: A4 (SDA), A5 (SCL)                - Pin Arduino: 10 (SS), 11 (MOSI), 12 (MISO), 13 (SCK)
```

1. Bus I2C / TWI (Two-Wire Interface)

- **Piedinatura su Arduino**: Pin **A4 (SDA - Data)** e Pin **A5 (SCL - Clock)**.
- **Architettura**: Bus multi-master / multi-slave a 2 linee con resistenze di Pull-Up esterne/interne.
- **Indirizzamento**: Il Master avvia la comunicazione inviando l'indirizzo univoco a **7 bit** del dispositivo Slave con cui intende interagire.
- **Libreria**: Gestito tramite la libreria standard **Wire.h**.

2. Bus SPI (Serial Peripheral Interface)

- **Piedinatura su Arduino**: Pin **10 (SS)**, Pin **11 (MOSI)**, Pin **12 (MISO)**, Pin **13 (SCK)**.
- **Architettura**: Bus Master/Slave a 4 linee:
    - **MOSI** (Master Out Slave In): Trasmissione dati dal Master allo Slave.
    - **MISO** (Master In Slave Out): Trasmissione dati dallo Slave al Master.
    - **SCK** (Serial Clock): Segnale di clock generato dal Master.
    - **SS** (Slave Select): Linea dedicata ad attivare lo Slave desiderato (a livello basso `LOW`).
- **Libreria**: Gestito tramite la libreria standard **SPI.h**.
### Gestione dell'Energia e Modalità di Risparmio Energetico (Sleep Modes)

Nei sistemi embedded alimentati a batteria, la riduzione dei consumi energetici è un vincolo di progetto primario. L'ATmega328P integra **5 modalità di risparmio energetico** attivabili tramite la libreria `<avr/sleep.h>`:

 ![[Pasted image 20261011153836.png]]_( tabella comparativa dei domini di clock attivi nei vari Sleep Mode )_

1. **SLEEP_MODE_IDLE** **(Light Sleep)**:
    - Arresta il clock della CPU e della Flash, mantenendo attivi i timer, il sistema di interrupt, l'ADC e i moduli seriali (SPI, UART, I2C).
    - Consente il risveglio rapido tramite interruzioni provocate dai timer o dagli eventi di rete.
2. **SLEEP_MODE_PWR_DOWN** **(Deep Sleep)**:
    - Arresta tutti gli oscillatori e blocca tutti i clock interni dell'MCU, riducendo l'assorbimento di corrente a frazioni di micro-ampere ($< 1\,\mu\text{A}$).
    - Il sistema può essere risvegliato unicamente da un **reset esterno**, dal **Watchdog** o da un **interrupt esterno sui pin INT0/INT1**.

```
// Esempio di codice per entrare in Deep Sleep (SLEEP_MODE_PWR_DOWN)
#include <avr/sleep.h>

void entraInDeepSleep() {
    set_sleep_mode(SLEEP_MODE_PWR_DOWN); // Seleziona la modalità Power-Down
    sleep_enable();                      // Abilita il bit SE (Sleep Enable)
    sleep_mode();                        // Mette la MCU in pausa qui!
    
    /* Il programma riprende da questo punto al risveglio tramite interrupt */
    sleep_disable();                     // Disabilita lo sleep dopo il risveglio
}
```
